# open-rush

동시 요청 환경에서 정확성과 성능을 비교하는 콘서트 예매 백엔드입니다.

## 설계

- 헥사고날 아키텍처와 DDD를 지향하며, 도메인 객체와 JPA 엔티티를 함께 사용합니다.
- 엔티티 ID는 DB가 생성하는 `Long`입니다. 현재 구현 범위는 도메인과 테스트입니다.

## 도메인

| 모델                   | 역할                                                       |
|------------------------|------------------------------------------------------------|
| `Concert`              | 공연 정보와 1인 구매 한도 N매                              |
| `Performance`          | 공연 회차와 예매 기간                                      |
| `PerformanceSeat`      | 회차별 좌석 재고·상태·점유한 예매 ID                       |
| `Reservation`          | 한 사용자의 한 회차 예매. 여러 좌석을 묶는 애그리거트 루트 |
| `ReservationItem`      | 예매 내부의 좌석별 항목과 예약 당시 가격                   |
| `ConcertPurchaseQuota` | 사용자·콘서트별 확보한 수량                                |
| `Money`, `SeatNumber`  | 금액과 좌석 번호 값 객체                                   |

## 핵심 정책

- **콘서트 생성 시 1인 구매 한도 N을 지정**합니다(양수). 해당 콘서트의 모든 회차에서 선점·확정 수량을 합산합니다.
- 예매 한 건에는 같은 회차의 중복 없는 좌석 1~N개가 포함됩니다.
- 선점 시 한도를 확보하고, 확정 시 유지하며, 취소·만료 시 반환합니다.
- 선점 기한은 기본 5분이며 예매 마감을 넘지 않습니다. 만료 시각부터 확정할 수 없습니다.
- 예매 전체를 함께 확정·취소·만료합니다. 부분 취소와 확정 후 환불은 아직 지원하지 않습니다.
- 종료된 예매와 항목은 이력으로 보존합니다. 좌석은 현재 점유한 예매 ID가 일치할 때만 변경합니다.

## 트랜잭션 경계 — 이후 구현

- 생성: 한도 확보 → 예매·항목 저장 및 ID 발급 → 모든 좌석 선점. 하나라도 실패하면 전체 롤백합니다.
- 확정: 예매 확정과 모든 좌석 확정을 함께 처리합니다. 한도는 유지합니다.
- 취소·만료: 예매 종료 전환이 성공한 경우에만 좌석과 한도를 함께 반환합니다. 반복 요청에서 이중 반환하지 않습니다.
- 유스케이스는 예매자·콘서트와 한도 모델의 일치 여부를 검증해야 합니다.
- 사용자·콘서트별 한도 행과 좌석에 대한 동시성 제어가 필요합니다. 현재 모델만으로 동시 요청을 보호하지는 않습니다.
- 저장소 포트·어댑터, 락 전략, Flyway 마이그레이션, 결제·대기열은 이후 추가합니다.
